# Agent Instructions

## Commands

- Install the exact local validators once: `./scripts/install-ci-tools /absolute/path/to/nvim-config-tools/bin`.
- Reproducible bootstrap into an isolated plugin/parser tree: `./scripts/bootstrap-config --xdg-root /absolute/path/to/nvim-config-xdg`.
- Reconcile the current private HOME runtime with a deterministic schema-v1 report: `./scripts/provision-runtime --non-interactive --report /absolute/path/under/home/report.json [--require-managed-tools] [--allow-network]`. It is offline by default; only `--allow-network` authorizes missing or stale plugins, tools, and parsers to be fetched.
- Full offline validation from the repo root: `PATH=/absolute/path/to/nvim-config-tools/bin:$PATH NVIM_CONFIG_XDG_ROOT=/absolute/path/to/nvim-config-xdg ./scripts/check-config`. It checks exact lock coherence, all pure/full-profile specs, startup, the exact StyLua/ShellCheck/actionlint/tree-sitter pins, host `cc`, and `git diff --check` with isolated state/cache/log paths.
- Startup smoke check from the repo root: `nvim --headless "+quitall"`
- Focused dependency-free specs can be run with `nvim --headless -u NONE -l tests/<name>_spec.lua`; startup/tooling specs need the full-config invocation provided by `scripts/check-config`.
- Formatting is configured inside Neovim through Conform, not a root-level CLI script:
  - Current buffer: `:FormatFile`
  - Toggle format-on-save globally: `:FormatToggle`
  - Toggle format-on-save for only the current buffer: `:FormatToggle!`
- Repository Lua style check: `stylua --check init.lua lua tests`

## High-level architecture

- `init.lua` is the entrypoint. It requires Neovim 0.12+, sets global options, leader keys, PATH tweaks, shared autocommands/keymaps, then loads `lua/config/*` modules and bootstraps plugins through `lua/config/lazy.lua`.
- `lua/config/lazy.lua` bootstraps `lazy.nvim` and loads plugin specs from `lua/plugins/`. Most features are implemented as one plugin or feature group per file under that directory.
- There is a second "pager profile" for when nvimpager loads this config (the symlink `~/.config/nvimpager -> ~/.config/nvim` plus nvimpager's `NVIM_APPNAME=nvimpager`). `lua/config/pager.lua` detects it (`M.active = vim.env.NVIM_APPNAME == "nvimpager"`); when active, `lua/config/lazy.lua` loads only the allowlist from `pager.specs()` (theme, Snacks, md-render.nvim, a slim treesitter with just `M.parsers`, and devicons) instead of `{ import = "plugins" }`. This keeps Mason/LSP/completion and the rest of the plugins from ever loading. Lazy is initialized before `:syntax enable`, so normal argv lifecycle events are observed without private `lazy.core` replay. Because a pager-only Lazy spec would prune a shared lock, `lua/config/lazy_lock.lua` copies `lazy-lock.json` to profile-local state and gives the writable copy to Lazy. `pager.setup()` frees nvimpager's `j/k/<Up>/<Down>` scroll maps and adds a pager-only `:SetFileType`/`<leader>ft` picker that strips ANSI escapes on the hidden source before applying the filetype. Markdown file arguments use normal detection; piped stdin can be forced with `NVIMPAGER_FILETYPE=markdown`. Markdown renders automatically in the pager; `:MarkdownView`/`<leader>mv` toggles between rendered and source views. Parser installation is explicit via `:NvimConfigParsersInstall`; pager startup never installs parsers.
- The full editor keeps Markdown source editable and unrendered. `lua/config/markdown_view.lua` owns `:MarkdownView`/`<leader>mv`, which opens one focused, read-only, live-updating `md-render.nvim` v3.10.3 tab per source. Invoking it again from the source focuses that tab; invoking it from the render closes the tab and returns to the source. `lua/config/markdown_layout.lua` centers the page at 90% of the usable width, capped at 120 columns; the separate code-block decorator labels fenced languages and shades their rows. The exact lock, loaded checkout, and private media guard are checked before rendering. Automatic images and Mermaid/PlantUML execution are disabled, leaving diagram fences as code blocks. `<leader>mp` (markdown-preview.nvim) stays editor-only.
- Diagrams (mermaid + PlantUML) are viewed on demand in a floating window via the unified `lua/config/diagram.lua` (`:DiagramShow [svg|ascii]`, default svg; registered in `M.setup()` from `init.lua`; skipped in VS Code). Keymap `<leader>md` is buffer-local to markdown/plantuml in the editor, but **global in the pager** (`pager.active`) so it works on any viewed content; from a rendered pager page it resolves the corresponding source location.
  - **Detection**: `diagram-view.nvim` extracts the selection, fenced block, or whole buffer; a `plantuml` filetype uses the whole buffer.
  - **svg mode** (image in a centered float scaled to fit; `q`/`<Esc>` closes): mermaid = `mmdflux -f svg` → `rsvg-convert -f png`; plantuml = `plantuml -tsvg -pipe` → `rsvg-convert -f png`. The PNG is shown via `Snacks.image.placement.new(scratch_buf, png, { inline, max_width, max_height })`. Chromium-free and ImageMagick-free (a PNG source skips Snacks' ImageMagick step). Needs `image = { enabled = true, doc = { enabled = false } }` in `lua/plugins/snacks.lua` and a Kitty-graphics terminal (Ghostty). PNGs cached by hash under `stdpath("cache")/diagram`.
  - **ascii mode** (text in a float): mermaid = `mmdflux`; plantuml = `plantuml -ttxt -pipe`. svg **falls back to ascii** when `Snacks.image.supports_terminal()` is false or an svg dependency is missing.
  - **Missing dependencies are announced** via `vim.notify` with the managed command (`:NvimConfigToolsInstall mmdflux` or `:NvimConfigToolsInstall plantuml`) or a host librsvg hint — nothing fails silently. Works in the editor and the pager.
  - **Reading view (`<leader>mv`)**: `:MarkdownView` opens or focuses a read-only render tab in the editor, closes it when invoked from the render, and toggles source/render mode in the pager.
  - **Whole-document browser preview**: `<leader>mp` uses markdown-preview.nvim in the editor only. Individual Mermaid and PlantUML blocks use `:DiagramShow` exclusively.
  - Renderer processes are generation-aware and asynchronous. The plugin owns cancel-safe sessions and its private v3 cache; writes are atomic, hostile entries are rejected, and host bounds come from `diagram_cache` local config.
  - External renderer installation is explicit and pinned through `:NvimConfigToolsInstall`; plugin startup never runs language package-manager installers.
- Runtime behavior splits early between the full terminal editor, nvimpager, and `vim.g.vscode`:
  - `lua/editor/vscode.lua` remaps the shared key vocabulary to VS Code actions.
  - `lua/editor/terminal.lua` defines the terminal-Neovim behavior and custom user commands.
  - Terminal-only command modules (menu, diagrams, LogWatch, LSP, clangd, Dev Container) are not required in VS Code. The pager receives only viewer/diagram commands, never IDE services.
- LSP/tooling is orchestrated by `lua/plugins/lsp.lua` and split by responsibility:
  - `lua/config/lsp_catalog.lua` is the single server/tool catalog; `lsp_servers.lua`, `lsp_navigation.lua`, and `lsp_neoconf.lua` own native registration, navigation, and project settings respectively.
  - `verified-tools.nvim`, `config.tool_bootstrap`, and the exact manifest own release and Mason installation. Startup registers only `config.tool_commands`; the lifecycle/core loads on the first runtime tool use or explicit lifecycle request. Neither startup nor Mason readiness plans, probes versions, attests, or accesses the network. `plan(name)` is targeted, `plan_all()` is explicit-only, and `:NvimConfigToolsInstall[!] [all|name]` is the explicit plan/install/retry/repair path. Core-owned verified shims precede local, host, release and Mason paths. Release proof binds the verified archive to every promoted file; Mason proof validates the raw receipt, declared executable-link map, canonical launcher targets, and a private `0600` receipt; transitive package/interpreter closure remains a documented limitation. Mason's read-only UI is command-lazy, `mason-lspconfig` is a dormant compatibility dependency with no runtime setup, native lspconfig loads independently on file open, and `NVIM_CONFIG_OFFLINE=1` blocks network without consuming an attempt.
  - `scripts/provision-runtime` is the explicit in-place runtime reconciler, distinct from isolated `bootstrap-config` and read-only `check-config`. It accepts only a canonical HOME-owned report path, confines XDG/state work below HOME (never `/localdata`), preserves unrelated plugin/parser/Mason extras and the committed lock, and writes a deterministic atomic `0600` schema-v1 report. Without `--allow-network` it only inventories and locally attests exact state; it never consumes an install attempt.
  - LSP servers are configured with native Neovim 0.12+ APIs (`vim.lsp.config` / `vim.lsp.enable`), not legacy `lspconfig.setup`.
  - `lua/config/python.lua` resolves root-local Python environments synchronously for ty, Neotest, DAP, and the REPL without invoking an environment manager or mutating process environment variables. It feeds an event-refreshed statusline cache; statusline render functions must remain cache-only. The attached ty root, then the nearest Python project marker, outranks the enclosing Git root so nested projects share one scope; `ty.toml` is native while `pyrightconfig.json` and `Pipfile` remain legacy root markers. Approved `ty.configuration.environment.python`, legacy interpreter settings, and root-scoped `:VenvSelect` choices override automatic discovery; keep interpreter paths lexical so virtualenv symlinks retain their identity. `project-python.nvim` publishes only provider-neutral snapshots; the host owns ty setting extraction and in-place LSP mutation. `lua/plugins/python.lua` deliberately removes venv-selector's `VenvSelectorUvDetect` augroup after setup because it runs install-capable `uv sync --script` automation; the manual picker remains enabled.
  - To add a language: add one catalog entry, one `register()` block in `lsp_servers.lua`, formatters/linters as needed, and the parser name in `lua/plugins/treesitter.lua`. Rust remains edit-only unless host/user `rust-analyzer` is found outside managed and Mason paths; Rust formatting stays disabled until `rustfmt` has an exact manifest contract. CMake language tooling remains an exact Mason pin with host PATH precedence.
  - ASM and PlantUML LSPs are intentionally absent. PlantUML rendering is provided by the pinned precompiled renderer, not a language server.
- VSCode-project interop (for repos that assume VSCode):
  - Neoconf owns its UI and global settings only. `config.project_settings` safely reads bounded JSONC from `.vscode/settings.json` and `.neoconf.json`; `:NvimConfigTrustProjectSettings` must approve their exact combined fingerprint before `lsp_neoconf.lua` may merge settings or honor `lspconfig.<server> = false`. Every use rereads and revalidates both files, so any lexical edit revokes the project layer. Neoconf project imports and live reload remain disabled. Existing server hooks are chained in their required order.
  - `.vscode/launch.json` is auto-loaded by nvim-dap on `dap.continue()`; `lua/plugins/dap.lua` aliases the VSCode adapter types `lldb` and `cppdbg` to codelldb (do not use the deprecated `load_launchjs`).
- `scripts/devcontainer-editor`, `lua/config/devcontainer.lua`, and `local-plugins/devcontainer-editor.nvim` own the host-first Dev Container workflow. The host adapter validates tmux's single `editor` pane and starts a detached coordinator with `run-shell -b`, an explicit pane ID, and a unique claim; it reports success only after observing that exact `starting`/`running` record, while timeout leaves extant state untouched. The coordinator holds a private advisory flock for its whole lifetime and checks every positive tmux mutation. It publishes `running` only after verifying an alive pane PID and workspace marker, and retires the record only after a verified host-Neovim respawn and durable positive ACK. Startup never downloads the CLI or tools. `exec --` remains argv-based, paths translate only through the registered host/container mapping, and host LazyGit/log/session actions use an owner-only spool whose secret exists only in `auth.json`; messages carry filename-bound UUIDv4/HMAC authentication, never the secret in argv/env/log. TUICR/publication is not transported. Any extant lifecycle record (`starting`, `running`, `stopped`, `error`, or `dead`) blocks fallback; only absence permits host fallback. See `docs/devcontainer-neovim.md`.
- `lua/config/editor.lua` is the shared navigation primitive: it opens targets in tabs and reuses an existing tab if that file is already open. LSP jumps, snacks.picker selections (via the custom `open_in_tab` confirm action in `lua/plugins/snacks.lua`), and the custom `gf` flow all rely on it.
- `lua/config/navigation_history.lua` records those shared semantic navigations as an exact global back/forward stack (`tabpage`, window, path, line, column). Full-editor `<C-o>`/`<C-i>`, `<leader>nh`, and the `NavigationBack`/`NavigationForward`/`NavigationHistory` commands use it, falling back to Neovim's native jumplist only before a semantic stack exists. History restoration must call `open_file_in_tab(..., { record_history = false })` to avoid recording itself.
- `lua/config/tabs.lua` owns full-editor tab closure and tab-title focus. `:CloseTab`, `<leader>q`, bufferline's native per-tab close button, and middle click route stable tabpage handles through it; right click opens the hierarchical menu. Closing the final work tab preserves buffers and opens the Snacks dashboard on a marked home tab. Bufferline labels follow the last focused non-floating window, so transient UI floats never replace a real tab name. Unmodified tabs show the close button while modified tabs show the modified marker. Selected bufferline highlights, including the close button, derive from `Visual` with a `PmenuSel` fallback.
- Native code review is implemented by `local-plugins/native-review.nvim` and composed by `lua/config/code_review.lua` in the user's ordinary tab. The plugin freezes exact Git models, owns inline/native split views and the three core floats, and persists owner-only versioned JSON. Diffview is deliberately independent and must not import review modules or regain review hooks. Current exact source may use LSP; historical old/panel buffers never attach, and historical-new `gd` may bridge only unchanged lines to current source. Clipboard export is repeatable; legacy bridge and delivery fields round-trip inertly, and linking/publication are not part of Neovim.
- `lua/config/viewer_commands.lua`, `lua/config/lsp_commands.lua`, and related `lua/config/*` modules define the custom user commands that glue plugins together into the editing workflow.
- `lua/config/menu.lua` is only a facade. Stable declarative descriptors live in `lua/config/menu/catalog.lua`, runtime actions in `actions.lua`, pure filtering and origin-target capture in `context.lua`, and the only allowed `menu.state`/`menu.utils` private compatibility seam in `backend.lua`. The searchable palette renders descriptors as `Namespace: Action` and includes a large curated `palette` surface; `palette`-only descriptors must never leak into the compact hierarchical `context` menu. Actions run against the buffer/window/selection captured before Snacks takes focus.
- `lua/config/log_watch.lua` follows files asynchronously by byte offset, bounds retained lines/bytes, preserves partial lines and handles truncation/rotation/recreation. Never replace it with a full synchronous `readfile()` loop, and never discard a modified buffer.
- `lua/config/toolchain.lua` is the source of truth for exact CI-host Neovim, validator and renderer versions plus release SHA-256 values. The Dev Container image supplies Neovim. `devcontainers-cli` is a managed dynamic npm release: only an explicit install (named or `all`) reads the `latest` dist-tag, then publishes an exact immutable bundle with private Node 24.20.0; runtime resolves only the offline active slot and never host node/npm or Homebrew. `PATH` precedence is verified shims, local-config paths, `~/.local/bin`, inherited host paths, managed releases, then Mason. Managed mmdflux/PlantUML and CI validators use precompiled assets; Mason npm packages need node/npm and PyPI packages need Python venv. Rust tooling is external-only and never enters this install manifest. Keep scripts, workflow pins, health text, docs, and tests derived from the manifest.

## Key conventions

- Use `<space>` as `mapleader` and `maplocalleader`. New mappings should use `<leader>` prefix.
- Prefer adding or updating plugin behavior in `lua/plugins/<feature>.lua` instead of expanding `init.lua`. The repo is organized around small Lazy specs plus matching helper modules under `lua/config/`.
- Imports stay at module scope. Products that must remain unloaded at startup are the sole exception and activate through the audited allowlist in `lua/config/deferred.lua`; do not add callback-local `require(...)` calls elsewhere.
- When adding terminal-only functionality, guard it with the existing VS Code pattern: `cond = function() return not vim.g.vscode end`.
- For new LSP work, follow the current native Neovim approach in `lua/plugins/lsp.lua`; do not reintroduce `require("lspconfig").<server>.setup(...)`.
- When opening files from picker results, diagnostics, or tool output, route through `require("config.editor").open_file_in_tab(...)` so navigation keeps the repo's tab-based behavior.
- Formatting is intentionally opt-in for saves: Conform is installed, but `vim.g.conform_format_on_save` starts as `false`.
- Custom commands and helpers usually surface failures with `vim.notify(...)` instead of silently doing nothing; match that behavior when adding filetype- or tool-dependent commands.
