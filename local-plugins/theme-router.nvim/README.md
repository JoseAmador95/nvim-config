# theme-router.nvim

Boundary: default/local/fallback theme selection, painter registry,
apply/repaint events, strict shared YAML state, and lexical legacy migration.
Themes, picker, commands, palette repaint, and OSC 11 stay outside.

`setup(opts)` injects the absolute state path, optional legacy path, default and
fallback names, generic painter, context, notification, and event callbacks.
The public surface is `register`, `selection`, `apply`, `repaint`, `select`,
`reload`, `persist`, and `reset`. `select(name)` paints and persists through one
composite operation. `reload()` rereads durable YAML; invalid YAML updates
validity while preserving the selected theme, active paint, and last-known-good
paint. Every returned selection and event value is caller-owned.

`status()` reports those selected, active, validity, and last-known-good states
separately and is safe before setup. `effective_config()` contains copied policy
without callbacks. Unknown setup options are rejected before state replacement,
teardown is repeatable, and `on_state_change(event)` failures are isolated.

The state directory also contains a permanent `.theme-router.lock`. It is an
owner-UID, single-link regular `0600` file opened and validated through the
pinned parent descriptor. A bounded 250 ms non-blocking advisory lock serializes
setup loading and legacy migration with `persist()` and the complete `reset()`
marker/delete cleanup. The lock pathname is never unlinked, avoiding a shared
lock-name replacement window; acquisition rejects symlinks and hardlinks.

The editable state is intentionally small:

```yaml
# Comments and blank lines are allowed.
version: 1
colorscheme: "vscode"
```

No other keys or versions are accepted. Writes atomically replace a real `0600`
file inside a real `0700` directory using descriptor-relative operations;
symlinks, hardlinks, non-regular targets, identity changes, oversized/truncated reads, and
ancestor swaps fail closed. Files and directories are secured through their
open descriptors, never by chmodding a pathname after validation. Target opens
are non-blocking so FIFOs and other non-regular entries cannot stall routing.
Every committed `mkdir`, publication, exchange, quarantine rename, and unlink
is followed by an `fsync` of the pinned parent directory. Cleanup moves an entry
through a second no-clobber quarantine after its final validation, so a late
replacement is preserved rather than deleted. A directory-fsync, close, or
cleanup failure after publication remains a successful committed write and is
returned, notified, and emitted as a structured warning; pre-commit file
`fsync`/close failures still fail the write.

When YAML is absent, only the exact Lua text previously generated by the host
adapter can be migrated. The YAML is written first and the legacy Lua file is
retained as recovery material, but is never executed. `reset()` first writes a
private `0600` `.legacy-migrated` marker and then safely deletes the YAML. It
does not persist the default: a later `setup()` therefore resolves the current
host default dynamically, while the marker prevents the retained legacy Lua
from being migrated again. Failures detected before replacement or deletion
leave the in-memory selection and YAML unchanged. If the OS mutation succeeds
but final parent revalidation detects drift, the operation reports failure,
keeps the in-memory selection unchanged, and explicitly makes no rollback
claim; the mutation remains confined to the previously opened private
directory.

This is a cooperative, owner-only namespace. POSIX has no atomic
compare-and-unlink primitive: after the last exact descriptor snapshot, a
hostile process running as the same OS UID could still replace a reserved name.
The owner UID is therefore the trust boundary; quarantine and the permanent lock
protect cooperating editor/pager processes, not adversarial same-user code.
